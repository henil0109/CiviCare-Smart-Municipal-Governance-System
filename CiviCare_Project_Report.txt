1. PROJECT OBJECTIVE & NEED
-------------------------------------------------------------
The rapid growth of urban areas has led to an increase in civic issues such as broken infrastructure, water supply disruptions, waste mismanagement, and electrical hazards. Traditional municipal reporting systems are often slow, paper-based, and lack transparency, leaving citizens frustrated and municipal staff overwhelmed.

Objective: 
CiviCare aims to bridge the gap between citizens and municipal authorities by providing an intelligent, transparent, and gamified digital platform. The system uses AI to automate the triaging of civic complaints, assigns them to the appropriate department, and allows citizens to track the resolution in real-time.

2. SCOPE AND LIMITATIONS
-------------------------------------------------------------
Scope:
- A public portal for citizens to register, verify their identity, and submit civic complaints with evidence (photos/documents).
- An AI engine that automatically categorizes issues, predicts priority, estimates costs, and assesses public safety risks.
- A hierarchical management system for Admins to oversee operations, and Supervisors to manage Field Teams.
- A gamification system that rewards citizens for active civic participation.
- An always-on AI Chatbot (CiviBot) to guide users, answer FAQs, and help navigate the platform.

Limitations:
- The AI Engine currently relies on an advanced keyword weighting and heuristic rule-based algorithm rather than a continuously learning neural network.
- Live GPS tracking for municipal vehicles is simulated in the current web-based deployment.
- Requires internet access, which may limit usability for non-digital citizens.

3. TECHNOLOGY STACK
-------------------------------------------------------------
Frontend:
- React.js (built with Vite)
- Tailwind CSS (for modern, responsive styling)
- Framer Motion (for smooth micro-animations and page transitions)
- React Router (for Single Page Application navigation)

Backend:
- Python (Flask Framework)
- JWT (JSON Web Tokens) for secure, stateless authentication
- Werkzeug (for secure password hashing)
- Brevo (Sendinblue) HTTP API for asynchronous transactional emails

Database:
- MongoDB (NoSQL database hosted via MongoDB Atlas)
- PyMongo (Python driver for MongoDB)

4. DATABASE STRUCTURE & MODELS
-------------------------------------------------------------
The NoSQL schema is built around the following core entities:

1. Users Collection:
   - Stores Citizens, Admins, Supervisors, and Field Staff.
   - Fields: username, email, password_hash, role, phone, ward, address, profile_photo.
   - Gamification Fields: xp, level, badges, impact_score.
   - Auth Fields: is_verified, verification_token, reset_token.

2. Complaints Collection:
   - Stores civic issues reported by citizens.
   - Fields: user_id, title, description, category, priority, status, photo_url, proof_url, location_address, ward.
   - Admin/Staff Fields: assigned_supervisor, assigned_unit, admin_remarks, work_log, timeline.
   - AI Fields: ai_analysis (predicted category, priority), resolution_report.

3. Teams Collection:
   - Stores operational field units.
   - Fields: name, supervisor_id, members (array of user IDs), specialization.

4. Notifications Collection:
   - Stores in-app alerts for users.
   - Fields: user_id, title, message, type (info/alert), is_read.

5. Inquiries Collection:
   - Stores contact form submissions.
   - Fields: name, email, subject, message, status, reply.

5. SYSTEM WORKFLOW & IMPLEMENTATION
-------------------------------------------------------------

Phase 1: User Onboarding & Auth
- A citizen registers on the portal. The backend sends an asynchronous verification email using the Brevo API.
- Upon clicking the link, the account is activated. The user logs in and receives a JWT token, allowing access to protected routes (like their Dashboard and Complaint Form).

Phase 2: Issue Reporting & AI Triage
- The citizen submits a complaint (e.g., "Huge pothole causing accidents on Station Road").
- The Flask backend routes the text to the `ai_module.py`.
- The AI Engine performs:
  1. Priority Prediction (assigns High priority due to the word "accident").
  2. Category Prediction (assigns "Roads & Infrastructure" based on "pothole" and "road").
  3. Risk Assessment (evaluates the threat level to public safety).
  4. Resolution Time Estimation (calculates target deadline).
  5. Cost Estimation (predicts repair costs based on severity).
- The complaint is saved in MongoDB, and an Admin receives a real-time notification.

Phase 3: Delegation & Resolution
- The Admin reviews the AI-triaged complaint via the Admin Dashboard and assigns it to a Supervisor specializing in Infrastructure.
- The Supervisor receives the task on their dashboard and dispatches a Team to the location.
- As the team works, the Supervisor updates the status (Pending -> In Progress -> Resolved). 
- Every status change updates the complaint's "timeline" field, which is visible to the citizen.

Phase 4: Closure & Gamification
- Once resolved, the AI generates a final Resolution Summary Report.
- The citizen who reported the issue is awarded XP (Experience Points) and potentially a Badge (e.g., "Active Contributor") for helping the city.
- The citizen receives an email/notification that their neighborhood has been improved.

6. CORE FEATURES & CONCEPTS
-------------------------------------------------------------
1. Automated AI Triage: Eliminates the manual sorting of complaints, drastically reducing the time it takes for a complaint to reach the right department.
2. Hierarchical Role-Based Access Control (RBAC):
   - Admin: Global oversight, analytics, staff creation, global assignment.
   - Supervisor: Manages specific teams, oversees localized tasks, updates statuses.
   - Citizen: Reports issues, tracks statuses, views public municipal info.
3. CiviBot AI Assistant: A persistent, 24/7 floating widget on the UI. It provides personalized guidance, answers FAQs, and contextually redirects users to login/registration or complaint forms based on their authentication status.
4. Civic Gamification: Applies game-design elements (XP, Levels, Badges) in a non-game context to encourage continuous community engagement.
5. Asynchronous Operations: Email dispatching is handled in background threads so it never blocks or slows down the user interface.
6. Modern UX/UI: Uses Glassmorphism, smooth Framer Motion transitions, and a dark/light mode friendly palette to provide a premium web experience.

7. SYSTEM DESIGN & ARCHITECTURE
-------------------------------------------------------------
- Client-Server Architecture: The React frontend operates independently of the Flask backend, communicating entirely via RESTful JSON APIs.
- Proxy Configuration: In local development, Vite proxies API requests to the Flask server (running on port 5000) to bypass CORS issues. In production, CORS is strictly managed via Flask-CORS.
- Stateless Backend: JWT tokens mean the backend doesn't need to manage server-side sessions, allowing the Flask app to scale horizontally if deployed on platforms like Render or Vercel.

8. RESULTS & IMPACT
-------------------------------------------------------------
By digitizing and automating the municipal complaint pipeline, CiviCare ensures:
- Faster Response Times: High-priority emergencies are instantly flagged.
- Higher Accountability: Every step is timestamped in a public timeline.
- Resource Optimization: AI predicts required team sizes and equipment, preventing resource wastage.
- Engaged Citizens: Gamification transforms complaining into a constructive, rewarding civic duty.
